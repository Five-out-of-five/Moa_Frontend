# MOA FE·BE 11/12 회의 — 안건 ①③ 공유 (프론트 담당 이홍근)

> 회의 메모에서 "확인 후 공유"로 보류된 안건 ① API 계약 과 안건 ③ 실시간(WebSocket) 에 대한 프론트 정리본입니다. 안건 ②(로그인·토큰 흐름 D안) 은 별도.

## 안건 ① API 계약 맞추기

### 현재 FE 알림 뼈대 vs 10/28 명세 — 주요 차이

경로 자체는 거의 일치합니다. 응답 shape 과 기능 범위에서 변경이 필요합니다.

| 항목 | 현 FE | 10/28 명세 | 조치 |
| --- | --- | --- | --- |
| 목록 응답 형태 | 배열 `Notification[]` | `PageResponse<NotificationResponse>` | 페이지네이션 적용 (목 포함) |
| 응답 필드 | `id / kind / message / targetUrl / readAt / createdAt` | `notificationId / group / type / title / content / room{roomId, name} / targetType / targetId / read / createdAt` | 타입 재정의. 한 줄 `message` → `title` + `content` 로 분리 |
| 읽음 표시 | `readAt: string \| null` (timestamp) | `read: boolean` | 낙관적 업데이트 로직은 유지, 필드만 교체 |
| 이동 목적지 | `targetUrl` (문자열) | `room{...} + targetType + targetId` | FE 가 조합해서 URL 구성 (명세에 명시) |
| 카테고리 | FE 자체 매핑 `kind → "업무/투표/…"` | 서버가 `group` 필드로 내려줌 — `MY_ACTIVITY / TASK / VOTE / SESSION / MEMBER_ROLE / SYSTEM` | 서버 `group` 그대로 섹션 라벨 사용, FE 매핑 제거 |
| 삭제 | 없음 | `DELETE /api/v1/notifications/{notificationId}` 존재 | 드로워 각 항목 메뉴에서 호출 추가 고려 |
| 알림 설정 | 링크 비활성화 | 전역 `GET/PUT /api/v1/notification-settings`, 방별 `GET/PUT /api/v1/rooms/{roomId}/notification-settings` | `/account/notifications` 화면은 후속 이슈로 복구. **effective 우선순위: 방 뮤트 > 방별 group > 전역 > 기본 ON, SYSTEM 항상 ON** |

### 타입 자동 생성 (Swagger → TS) 도입 의견

**찬성**. 응답 shape 반복 수정 비용이 큽니다. 알림 한 도메인에서만 위 7건이 바뀌는데, 다른 도메인(방·업무·투표 각 18~22건) 작업 들어가면 수동 유지 비용이 폭증합니다.

- 도입 제안: BE 가 `springdoc-openapi` 로 `/v3/api-docs` 띄워 주시면, FE 에서 `openapi-typescript` 로 `types/api.d.ts` 를 자동 생성합니다. 공용 봉투 (`{success, data}`) 만 FE 매퍼에서 벗깁니다.
- 도입 전까지는 **목 데이터를 명세 "응답 data" 예시 그대로 교체**해 두면 BE 붙을 때 shape 흔들림을 최소화할 수 있습니다.

### 명세 변경 알림 채널

GitHub PR 에 `[명세 변경]` prefix + Slack/카톡 특정 쓰레드로 통일 선호합니다. 변경 범위 한 줄 (`Notification.kind → type, read 로 변경`) 만 남겨도 충분합니다.

## 안건 ③ 실시간(WebSocket) — 명세 20번 Realtime 기반

### 연결 단위 (제안: 전역 1개 + 토픽 구독) — 명세와 일치, 확정 가능

- 로그인 직후 `/ws` CONNECT 1회
- 즉시 구독: `/user/queue/notifications`, `/user/queue/channels` — 로그인 전 세션에서 상시 유지
- 방 진입: `/topic/rooms/{roomId}` + `/topic/rooms/{roomId}/presence` 추가 구독, 이탈 시 해제
- 채널 진입: `/topic/channels/{channelId}` + `/topic/channels/{channelId}/typing` 추가 구독, 이탈 시 해제

### 인증

D안(같은 도메인·쿠키) 확정으로 STOMP 헤더 토큰 대신 **쿠키 기반 인증 가능**. 기존 STOMP 토큰 인증(BE-3) 수정 필요.

FE 는 `SockJS` 또는 네이티브 `WebSocket` + `@stomp/stompjs`. `withCredentials: true` 로 쿠키 자동 전송.

### 끊김 · 재연결 처리

- `@stomp/stompjs` 의 `reconnectDelay: 5000ms` + exponential backoff
- 서버 하트비트 60초 끊김 = 오프라인 (명세 기준) → 재연결 후 **알림 목록 API 재조회로 누락분 수신** (명세: "미접속 중 생긴 알림은 다음 접속 때 목록 API 로 확인")
- 재연결 성공 시 활성 방·채널 토픽 재구독은 **FE 책임** (서버가 세션 복원 안 함)

### 이벤트 목록 (명세 20번) — 수신 처리 분리안

| 토픽 | 이벤트 타입 | FE 반응 |
| --- | --- | --- |
| `/topic/rooms/{id}` | `RoomEvent` (LAYOUT_CHANGED · WIDGET_EDITING · ROOM_UPDATED/DELETED/INACTIVATED · MEMBER_JOINED/LEFT/UPDATED · CARD_CREATED/UPDATED/MOVED/DELETED 등) | 대시보드 위젯·레이아웃 재조회 트리거 (전면 revalidate 가 아닌 영향 범위만) |
| `/topic/rooms/{id}/presence` | `PresenceEvent { accountId, online }` | 사이드바 DM 접속 상태 점 토글 |
| `/topic/channels/{id}` | `ChannelEvent` (MESSAGE_CREATED/UPDATED/DELETED · CHANNEL_UPDATED/DELETED) | 채팅 본문 스트림 반영 |
| `/topic/channels/{id}/typing` | `TypingEvent { accountId, displayName, typing }` | 입력 중 표시. **TTL 5초**, 본인 제외. 문구 규칙 FE |
| `/user/queue/notifications` | `NotificationEvent { notification, unreadCount }` | 드로워에 push + 헤더 배지 즉시 갱신 (기존 revalidate 패턴 대체) |
| `/user/queue/channels` | `MyChannelEvent` (UNREAD_CHANGED / INVITED / KICKED / DIRECT_UNHIDDEN) | 사이드바 뱃지·새 1:1 표시 |

### 송신 이벤트

- `/app/rooms/{id}/widgets/{widgetId}/editing` — 위젯 편집 중 표시 (저장 X, 전달만)
- `/app/channels/{id}/typing` — **3초에 1회 debounce** (서버 저장 안 함)

### 세부 미정 (다음에 확정 필요)

- 재연결 시 "마지막 받은 이벤트 시점부터 미싱분 다시 보내 달라" 가 필요한지 (지금 명세는 "목록 API 로 확인" 이라 1회 수신 전제)
- 토큰·쿠키 만료로 `/ws` 가 401 뜰 때 재발급 후 재연결 플로우 (미들웨어 refresh 와 동기)
